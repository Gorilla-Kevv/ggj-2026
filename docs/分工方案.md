## 五、协作规范

### Git分支策略

```
main
  └── dev
        ├── feature/core        (程序A)
        ├── feature/enemies     (程序B)
        ├── feature/interact    (程序C)
        ├── feature/levels      (关卡组)
        └── feature/audio       (D13 程序A)
```

- 每人从 `dev` 开分支，完成后提 PR
- 每日至少合并一次 `dev`
- 程序B和C需要频繁拉程序A的更新（`Global`、`player.gd` 变更直接影响他们）

### 文件所有权

| 目录 | 所有者 | 备注 |
|------|--------|------|
| `src/autoload/` | **程序A** | B/C可读，修改需告知A |
| `src/actors/player.gd` | **程序A** | B的敌人调用 `player.die()` |
| `src/actors/enemies/` | **程序B** | 继承A提供的架构 |
| `src/interactables/` | **程序C** | 基类使用A的 `Global.selected_target` |
| `src/environment/` | **程序C** | 环境机制在此 |
| `src/systems/` | **程序A** | 核心系统，修改需评审 |
| `src/ui/hud.gd` `wind_line.gd` | **程序A** | |
| `src/ui/boss_health.gd` | **程序B** | |
| `src/level/` | **程序A** | 关卡管理和检查点 |
| `src/scenes/level_*.tscn` | **关卡组** | 引用A/B/C提供的脚本 |
| `assets/` | **美术组** | 程序可引用，不可直接修改 |

### 程序间接口约定

**程序B（敌人）↔ 程序A：**
- 调用 `Global.selected_target` 判断当前选中目标
- 敌人接触玩家 → 调用 `player.die()`
- Boss吸气态 → 需要访问 `Global.selected_target` 判断哪些物体可被吸入
- 敌人眩晕 → 由程序C的交互物（如岩柱砸中）触发 `enemy.stun()`

**程序C（交互物）↔ 程序A：**
- 交互物 `_ready()` 中加入 `"interactable"` 组：`add_to_group("interactable")`
- 接收风力：实现 `apply_wind_force(force: Vector2)` 方法
- 从 `Global.selected_target` 获取当前选中状态
- 交互物碰撞到敌人 → 调用 `enemy.stun(duration)`

**程序B ↔ 程序C：**
- Boss吸气态吸入碎石（C的交互物）→ 交互物需能判断是否正在被Boss吸入
- 岩柱倒塌砸中敌人（B的 drone/researcher）→ 需统一碰撞信号

**关卡组需要知道的：**
- 所有交互物拖入场景后自动加入 `"interactable"` 组
- 关卡根节点挂 `level_manager.gd`，设置 `next_level_path`
- 检查点用 `checkpoint.gd` 场景，拖入关卡
- 出生点用 `Marker2D` 节点名 `"SpawnPoint"`
- 放置敌人时设置其 `patrol_points` / `patrol_path` 等导出变量

**美术组需要知道的：**
- TileMap 贴图集 32×32px
- 主角4帧旋转 + 1帧闲置
- 敌人精灵：闲置/移动/攻击（Boss需涡轮开关两态）
- 粒子贴图白色基础，引擎内调色

## 七、风险与缓冲

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 风力手感不佳 | 中 | 核心崩塌 | D3前若手感不达预期：简化操作，移除R键切换，风仅吹主角 |
| Boss三态逻辑复杂 | 中 | D12延期 | 降级为单态Boss（平静态+弹幕），飓风期改场景固定事件 |
| 程序B/C依赖A的接口变更 | 中 | 返工 | A的 `Global` 和 `player.gd` 在D4后冻结接口，后续只加不删 |
| 美术产能不足 | 高 | 占位素材上线 | 不阻塞关卡搭建——先搭玩法后换皮 |
| 关卡难度曲线不理想 | 中 | 体验差 | D13测试后集中调整：加减敌人、检查点间距、能量回复速度 |
| 三人并行合并冲突 | 低 | Git混乱 | 每日合并 `dev`，A负责最终合并审核 |
